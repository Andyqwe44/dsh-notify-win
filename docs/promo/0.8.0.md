## 一句话

DSH 跑完活、或者等你回话的时候，Windows 会像 QQ 一样提醒你：原生 toast 弹出，被忽略就在 DSH 自己的托盘图标上亮红点。

## 三条卖点

1. **红点长在 DSH 自己的托盘图标上**——不新增托盘图标、不改图标本体；Windows 把它收进 `^` 溢出区时，自动改画到任务栏按钮。
2. **事件驱动，几乎不耗电**——空闲 10 秒 CPU 0.0 ms；闪烁时每帧只有一次 `WM_TIMER` 加一次 shell 位置查询。
3. **说清楚为什么停**——正常完成 / 输出超限 / 前置拦截 / LLM 失败（带错误码和重试次数）/ 被取消，各有各的通知；设置就在「插件 → dsh-notify-win」页里，不往「设置」里塞条目。

## 短版文案（X / 微博 / 群聊，约 130 字）

> 用 DSH 跑长任务最大的问题是：它跑完了你不在电脑前。
> 给 DSH 写了个 Windows 通知插件 dsh-notify-win：任务完成/需要你回答时弹原生 toast，被忽略就在 DSH 自己的托盘图标上闪 QQ 式红点，切回前台自动停。事件驱动，空闲 0.0 ms CPU。设置直接长在插件页里。
> `dsh plugin --profile desktop add dsh-notify-win`

## 长版文案（掘金 / 公众号）

**标题**：给 DSH 做了个"QQ 式"提醒：红点画在它自己的托盘图标上

正文提纲：

1. 痛点：DSH 跑完一个长任务，人不在电脑前；Windows 通知容易被专注助手吞掉；任务栏暖流又太含蓄。
2. 做法：原生 toast（点击直达对应会话）→ 没人理就亮红点。红点不是新托盘图标，而是覆盖在 DSH 既有托盘图标格子上的**点击穿透分层窗口**（`UpdateLayeredWindow` + `Shell_NotifyIconGetRect` 定位），图标本体不动，helper 退出红点即消失。
3. 取舍：Windows 不提供"托盘图标位置变化"事件，所以每帧亮起时读一次位置；其余全部事件驱动（`WM_TIMER`、`WM_DISPLAYCHANGE`、前台钩子），实测空闲与闪烁 10 秒 CPU 都是 0.0 ms。
4. 溢出兜底：图标被收进 `^` 时查不到格子，两次落空就自动改用任务栏按钮角标（`ITaskbarList3::SetOverlayIcon`）。
5. 配置：每个事件独立勾选 toast / 红点 / 暖流，选"立即"还是"toast 超时后"；策略、时机、红点时长全在「插件 → dsh-notify-win」页里，即时生效。
6. 依赖：Windows 10/11 + .NET 10 Desktop Runtime。
